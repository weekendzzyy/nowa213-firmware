# v15.0 三屏显示 + NFC 交互固件 — 需求文档

> 状态：**已确认（2026-09-13）**——D1~D5 全部定案，见 §10
> 日期：2026-09-13
> 基线：v14.4（时钟单页固件，95 门局部刷新，81 项版面断言）
> 硬件事实依据：`docs/nowa213_flash_research.md` §15（FM11NC081 NFC 通道芯片调查）

---

## 1. 目标

把价签从「单一时钟」升级为「**三页显示 + 手机 NFC 一贴交互**」的设备：

1. **三页显示**：时间页 / 月历页 / 图片页，页面可切换；
2. **NFC 交互通道**：手机贴一下 = 翻页；手机写命令 = 执行指定功能（切页、开蓝牙窗口、校时等）；
3. **蓝牙省电模式**：BLE 可关闭，需要时由 NFC 命令开启限时窗口（默认 5 分钟自动关闭）。

### 非目标（本轮不做）

- NFC 传图片（共享区只有 ~900 字节，传图仍走 BLE）；
- 月历页逐格农历（字库与版面密度不够，列为后续版本可选）；
- 通过 NFC 做物理断电（FM11NC081 无电源开关管，做不到彻底断电，只有软件级深睡）；
- iOS 快捷指令动态校时（iOS 只能写固定内容，动态时间戳需安卓 + Tasker 或专门 App）。

## 2. 三页定义

### 2.1 页面 1 — 时间页（现状 v14.4 版面，不变）

- 行 1 日期 + 星期 + 温度 + 电压；行 2 DSEG14 大时钟；行 3 农历 + 节气 + 符文 + 广播名/版本号；
- 刷新订阅：**每分钟局部刷新**（95 门）+ 每小时全刷 + 死区全刷（温度/电压）+ 夜间 0:00–5:59 不刷新；
- 本页逻辑不改，原样搬进页面框架。

### 2.2 页面 2 — 月历页（新增）

| 项 | 规格 |
|---|---|
| 表头 | `2026年9月`（大字，居中） |
| 星期行 | `一 二 三 四 五 六 日` 单字（字库已有），周一与周末用灰度/位置区分 |
| 日期网格 | 7 列 × 5~6 行，数字 1~31（字库已有）；本月 1 号按星期对齐 |
| 今天高亮 | **反色块**（白底黑字 → 黑底白字），不新增字形 |
| 装饰 | 底部沿用行 3 样式（农历/节气/符号/广播名），保持家族观感 |
| 周起始 | **周一起始**（已定，D3） |
| 是否带农历 | **纯公历**（已定，D4）；农历逐格列为后续版本 |

- 刷新订阅：**仅午夜日变时全刷一次**（跨月自然由日变触发重排）；无每分钟局部刷新；
- 意义：挂墙上当月历时，一天只刷一次，耗电比时间页低一个量级。

### 2.3 页面 3 — 图片页（复活 v2/v3 管线）

| 项 | 规格 |
|---|---|
| 内容 | 用户通过 BLE 上传的图片（flash 存储，4000 字节 1bpp，断电不丢） |
| 无图占位 | 显示提示文字（需扩充 Unifont 子集几个汉字，生成器加字即可） |
| 红色层 | v1 **不做**（黑白显示）；BWR 红色层列为后续版本 |
| 传图 | 走现有 BLE 管线（opcode 0x01 存 flash + 显示；0x04 TIFF 解码同样保留） |
| 刷新订阅 | **零定时刷新**——只在切页/传新图时全刷 |

## 3. 页面框架（核心机制）

1. **页面状态**：1 字节存 flash（`USER_IMG_FLASH_ADDR` 区域内约定字节），掉电池、OTA 均不丢；上电读回直接显示上次的页。
2. **切页 = 全刷**：两页内容完全不同，局部刷新会重影；切页是低频动作，全刷（~2 s）代价可忽略。**铁律，无例外。**
3. **每页只订阅自己的刷新事件**（框架按页分发）：

| 事件 | 页1 时间 | 页2 月历 | 页3 图片 |
|---|---|---|---|
| 每分钟 | 局部刷新 | — | — |
| 每小时 | 全刷 | — | — |
| 午夜日变 | （由小时全刷覆盖） | **全刷（重排当月网格）** | — |
| 切页 | 全刷 | 全刷 | 全刷 |
| 温度/电压死区 | 全刷 | —（本页不显示） | — |

4. **非时间页的唤醒策略**：仍需醒来维护时钟（`current_unix_time` 追补），但**不驱动屏幕**；唤醒间隔可放宽（实现细节，前提：时基追补必须用 `while`，遵守 v9.0 教训；休眠间隔 < 268 s 定时器回绕上限）。
5. **夜间 0:00–5:59 静默规则**在所有页生效（时间页照旧不刷；月历/图片页本来就无定时刷新）。
6. BLE（校时/传图/OTA）在**任何页面**都可用（受 §5 电源模式约束）。

## 4. NFC 交互通道（新增）

### 4.1 硬件事实（§15 调查结论，不再重查）

- 芯片：复旦微 **FM11NC081**，ISO14443-A 双界面通道芯片，I2C 从地址 `0xAE`（SDA=PC0, SCL=PC1, CS=PC6, **IRQ_N=PC4**，开漏低有效：手机靠近/读写时拉低）；
- 共享 EEPROM ~900 字节，**手机（经 NDEF/Type4）与 MCU（经 I2C）双方可读写**，数据掉电保持；
- 当前固件只初始化了它，功能全部未用。

### 4.2 交互模型（投递式）

```
手机贴一下 ──写命令──▶ FM11NC081 共享区（EEPROM 存住，不怕 MCU 在睡）
PC4 IRQ 拉低 ──▶ 唤醒 MCU（gpio pad wake）──▶ I2C 读命令 ──▶ 执行 ──▶ 清命令槽 + 写回状态
```

- **投递式**：命令写进 EEPROM 就存住了，不要求 MCU 此刻醒着；MCU 拾取可以滞后几秒；
- 手机端用 **NFC Tools 等 App 写自定义记录**；固件做**最小 NDEF/TLV 解析**定位自定义负载（不做完整 Type4 APDU 协议栈）。

### 4.3 命令表（v1 定义，后续可扩充）

共享区命令块格式：`[magic 0xA5][cmd][len][payload...][sum]`；固件执行后**清空 magic**（防重复执行）并回写状态块。

| cmd | 名称 | payload | 行为 |
|---|---|---|---|
| `0x01` | 翻下一页 | 无 | 页面循环 1→2→3→1（等效于空贴） |
| `0x02` | 切指定页 | 1 B 页号(1..3) | 直接切 |
| `0x03` | 开蓝牙窗口 | 1 B 分钟数(1..30) | 打开 BLE 广播，超时自动关（见 §5） |
| `0x04` | NFC 校时 | 4 B unix 时间戳（大端） | 设置系统时间（**不需蓝牙**） |
| `0x05` | 强制全刷 | 无 | 当前页全刷一次 |
| `0x06` | 设蓝牙模式 | 1 B（0=省电 1=常开） | 切换 §5 的电源模式 |
| `0x10+` | （保留） | — | 后续扩展 |

### 4.4 交互语义

- **空贴**（无命令数据）：**翻下一页**（已定，D1；手机任何 NFC App 碰一下即触发，无需写数据）；
- 带合法命令：执行命令；magic 不对/校验失败：按空贴处理（容错）；
- **状态回读**：MCU 把 `[版本][电量 mV][温度][当前页][上次命令结果]` 写入状态块，手机贴一下即可读取（无需 App 定制，NFC Tools 直接读）；
- **去抖**：场持续存在（手机贴着不动）只触发一次；IRQ 上升沿（离开）复位状态机。

### 4.5 安全边界

- 任何有 NFC 手机 + 物理接触的人都能写命令——个人设备**接受**此风险；命令带 magic 前缀做最低限度防误碰。后续可选：命令带 4 字节配对码。

## 5. 蓝牙电源模式

| 模式 | 行为 | 适用 |
|---|---|---|
| **省电模式**（默认，已定 D2/D5） | BLE 广播**关闭**；NFC 命令 `0x03` 开窗，默认 **5 分钟**自动关 | 日常挂墙 |
| 常开模式 | 现状：10 s 广播间隔永不关 | 频繁调试期 |

- 开窗期间可做：BLE 校时、传图、OTA、切页——全部现有功能；
- **引导规则**：每次固件升级重启后，BLE 强制常开 10 分钟（保证升级后能立即校时/配置，避免「鸡生蛋」），之后进入所选模式；
- 省电收益要诚实：BLE 广播本来只占几 µA，**预计省 5% 左右**——本需求的动机主要是交互体验（贴一下才开机服务），不是省电。

## 6. 校时（双通道）

| 通道 | 流程 | 依赖 |
|---|---|---|
| BLE（现有） | web_uploader 连接 → 发时间 | 蓝牙窗口开着 |
| **NFC（新增）** | NFC Tools 写 `0x04 + 时间戳` → 贴一下 | 只需手机 + NFC App |

- OTA 刷机后的标准流程变为：贴一下（NFC 校时）→ 完事，不再强制连 BLE；
- 时间戳用固件现有 unix 时间体系（UTC+8 已在固件内处理）。

## 7. 验收标准

1. 三页各自渲染正确：离线预览工具能渲染三页（`render_screen_preview.py` 扩展 `--page` 参数），版面与本文档一致；
2. `verify_v14_layout.py` 扩展为多页断言（日历网格几何、图片页占位、页面常量），全部 PASS；含否定性自检；
3. 页面状态掉电池不丢（拔电池重装，回到上次页）；
4. NFC 命令**恰好执行一次**（同一命令不会被后续唤醒重复执行——magic 清除机制生效）；
5. 蓝牙窗口：命令触发后可连接，默认 5 分钟后广播停止；
6. NFC 校时误差 ≤ 1 s（写入时刻与固件接受时刻差）；
7. 月历页/图片页期间**无每分钟屏幕刷新**（用诊断计数器或电流观察确认）；
8. 切页无残影（全刷路径）；月历 1 号对齐星期正确（验证器穷举 2026–2050 每月第一天）；
9. 发布流程照旧：tag + 发布件 SHA256 + 干净检出重建逐字节一致 + `_end_bss_ < 0x850000`。

## 9. 风险与边界

| 风险 | 对策 |
|---|---|
| FM11NC081 NDEF 偏移不确定 | v15.2 先用 NFC Tools 实测写入布局、抓 I2C 读回验证；固件 TLV 解析留容错 |
| 深睡 RAM 不保留 | 页面状态/模式存 flash；唤醒路径重跑 `init_nfc()` |
| 手机贴着不动反复触发 | IRQ 沿状态机 + 场离开复位 |
| SRAM 只剩 4.1 KB | 三屏方案零新增大缓冲（图片复用 `epd_buffer`）；日历渲染直接画入显示缓冲 |
| iOS 无法写动态时间戳 | 校时命令可由 Android/他人代写，或退回 BLE 校时 |
