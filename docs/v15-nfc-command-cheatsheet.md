# v15 NFC 命令发送速查卡（手机端）

> 用途：用手机 NFC 写 App（NFC Tools / NXP TagWriter 等）向汉朔 Nowa-213R-N 价签发命令的现场查阅卡。
> 适用：固件 v15.x（三屏 + NFC 交互）。基线：`docs/v15-requirements.md` §4。
> 状态：命令定义已定（D1~D5 已确认），**v15.2 已实现命令通道**；EEPROM 偏移与 NDEF 头部布局仍待真机实测钉死（见 §9）。

---

## 0. ⚠ 先看这里：固件 NFC 能力现状

**2026-09-13 复核**：NFC 能力随版本递进，当前（v15.2）已能收命令。历史版（仅留作对照）：

- v15.0：`nfc.c` 全文只有 `init_nfc()`（29 行），**NFC 是摆设**，写任何记录无反应；

## 1. 信封格式

```
[ magic 0xA5 ] [ cmd ] [ len ] [ payload ... ] [ sum ]
```

- `magic`：固定 `0xA5`，固件以此识别「这是命令」。
- `cmd`：命令号（`0x01`~`0x06`）。
- `len`：payload 字节数。
- `payload`：参数（见命令表，无参 = 0 字节）。
- `sum`：校验和 = `magic ⊕ cmd ⊕ len ⊕ payload[0] ⊕ ...` 的 8 位 XOR。固件校验失败按「空贴」容错。

执行后固件**清空 magic** → 同一条不会被后续唤醒重复执行。

## 2. 命令速查表（完整帧，复制即可写）

下表为「裸字节」形态；文本形态见 §3。

| 想做的事 | cmd | payload | 完整帧（hex，空格分隔） | v15.2 结果 |
|---|---|---|---|---|
| 翻下一页（= 空贴） | `0x01` | — | `A5 01 00 A4` | ✅ 切下一页 |
| 跳到第 1 页 | `0x02` | `01` | `A5 02 01 01 A3` | ✅ 切到第 1 页 |
| 跳到第 2 页 | `0x02` | `02` | `A5 02 01 02 A4` | ✅ 切到第 2 页 |
| 跳到第 3 页 | `0x02` | `03` | `A5 02 01 03 A5` | ✅ 切到第 3 页 |
| 「开蓝牙窗口」 | `0x03` | `NN` | `A5 03 01 05 A2` | ⚠ 接受为空操作（BLE 本就常开，见 §5.1 铁律） |
| NFC 校时 | `0x04` | 4B 时间戳 | `A5 04 04 xx xx xx xx sum`，见 §5 | ✅ 设时（无需 BLE） |
| 强制全刷当前页 | `0x05` | — | `A5 05 00 A0` | ✅ 立即全刷当前页 |
| 切省电模式（关广播） | `0x06` | `00` | `A5 06 01 00 A2` | ❌ **拒绝**（状态 2，§5.1 铁律：命令通道未真机验收前禁止关广播） |
| 设常开模式 | `0x06` | `01` | `A5 06 01 01 A3` | ✅ 接受（即当前状态，无变化） |

> ⚠ **蓝牙电源铁律（docs/v15-requirements.md §5.1）**：v15.2 **不实现、不暴露**「省电模式 = 关广播」。
> 因此 `0x06 mode=0`（关广播）被固件拒绝（状态码 2），`0x03`（开窗口）因窗口本就永久开着成为空操作。
> 只要这条铁律在，设备**始终 BLE 可达**，坏帧不可能软变砖；要动「默认关广播」须等 NFC 命令通道
> 真机验证通过（v15.3 或以后）后另行放开。

## 3. 两种写入形态

手机 App 写 NDEF 记录时，有两种填法，固件都认（以 v15.2 实现为准）：

### A. 文本十六进制串（推荐，兼容性最好）
把整帧写成**一行 ASCII 十六进制文本**，例如翻页就写：
```
A50100A4
```
任何能写「文本 / 自定义记录」的 App 都能用，不要求 App 支持裸二进制输入。固件读取后按 ASCII→字节解码再校验。

### B. 裸二进制负载（精确）
在支持 hex / raw 输入的 App 里，直接填字节：
```
A5 01 00 A4
```
或 `A50100A4`（无空格）。

**实操建议：优先用 A 文本串形态**，避免 App 把高位字节（如 `A5`）误编码成多字节 UTF-8，导致固件解析失败。

## 4. 自己算一帧（开非 5 分钟的蓝牙窗口等）

公式：`sum = 0xA5 XOR cmd XOR len XOR 所有 payload 字节`（结果取低 8 位）。

例：跳到 **第 3 页** → `cmd=0x02`, `payload=0x03`
- 帧 = `A5 02 01 03`
- `sum = A5^02^01^03` = `A5^02=A7`, `^01=A6`, `^03=A5`
- 完整帧 = `A5 02 01 03 A5`
- 文本串 = `A5020103A5`

（注：`0x03` 开蓝牙窗在 v15.2 为无操作，算帧公式相同但写进去不会改 BLE 状态，见 §2。）

更多可用文末 Python 片段自验。

---

## 5. 校时命令怎么填时间戳

`0x04` 的 payload 是 **4 字节大端 unix 时间戳（UTC）**。

⚠ 北京时间 = UTC+8，**先减 8 小时再算 unix**。

获取时间戳的方法：
- 在线：epochconverter.com（填 UTC 时间）。
- 安卓 Tasker：`%TIMES` 直接给当前 UTC 秒。
- 手算示例（2026-09-13 16:24:55 北京）：
  - UTC = 2026-09-13 08:24:55
  - unix = 1789287895 = `0x6AA65DD7`
  - 大端 4 字节 = `6A A6 5D D7`
  - 完整帧：`cmd=04, len=04, payload=6A A6 5D D7`
  - `sum = A5^04^04^6A^A6^5D^D7 = E3`
  - → `A5 04 04 6A A6 5D D7 E3`
  - 文本串：`A504046AA65DD7E3`

## 6. 用 NFC Tools 发送的步骤

### 6.1 中文界面「添加记录」该选哪一项

NFC Tools（中文版）「添加记录」列表里有二十多项，对我们有用的只有两项：

| 列表项 | 英文 | 选不选 | 说明 |
|---|---|---|---|
| **文本** | Text | ✅ **首选** | 把整帧写成一串 ASCII 十六进制（§3-A），如 `A50100A4`。免费版就能写；且**不会**把 `A5` 这种高位字节按 UTF-8 编码成两字节（最常见的坑） |
| **数据** | Data / Custom record | ⭕ 备选 | 列表最下面那条「添加个性化的记录」= 外部类型/自定义记录，要填**类型名称 + 数据负载**，支持十六进制字节。以后要精确发二进制时用 |
| URL / URI、个性化 URL、Wi-Fi、蓝牙、联系人、位置、短信… | — | ❌ **别选** | 这些是「语义化」记录，手机会弹窗去执行动作，内容也不是我们约定的命令帧格式，固件解析不了 |

> 最终该选哪一项（以及固件认哪种 NDEF 记录类型）以 v15.2 的 TLV 解析实现 + 真机实测为准，见 §9。

### 6.2 操作步骤

1. 安装 **NFC Tools**（Android / iOS，免费版足够写文本记录）。
2. 打开 App → 切到 **写（Write）** 标签。
3. 点 **添加记录（Add a record）** → 选 **文本（Text）**（要裸字节则选 **数据（Data）**）。
4. 在「内容 / 负载」里填 §3-A 的文本串（如 `A50100A4`）。选「数据」记录时类型名可随意填（如 `n`），不影响解析。
5. 确认添加 → 点 **写（Write）** → 把手机**背面贴**价签 NFC 区（芯片在屏后，贴近屏中心偏一侧）。
6. 听到「写入成功」提示即完成。固件在下次唤醒时拾取命令（贴一下后通常 1~3 秒内生效）。

> 若用支持 Raw / hex 的 App（NXP TagWriter 的 Raw data、NFC Tools Pro），可在 §3-B 裸字节形态直接写，效果相同。
>
> **硬件前提**：主板 NFC = 复旦微 **FM11NC081**，作 **NFC Forum Type 4 Tag**，用户共享区 ~900 B、NDEF 区 200 B ⇒ 我们最长的帧（NFC 校时 8 字节）绰绰有余，无需装专用 App。
> 现在就可以先用 NFC Tools 的 **读（Read）** 贴一下价签，确认手机能认出这块标签（天线在屏后，要找位置）—— 这一步不依赖固件，能提前验证耦合，是 v15.1 能不能做的前提。

## 7. 读回状态（确认命令生效）

- 用 NFC Tools 的 **Read（读）** 标签贴一下价签，可见共享区 `0x00E0` 起固件回写的**状态块**
  （16 字节，首字节固定 `0x5A` 便于辨认）：
  `[0x5A][主版本][次版本][电量mV高][电量mV低][当前页][上次命令码][上次结果]`
  - `上次结果`：`0`=执行成功、`1`=坏帧/未知命令、`2`=被安全铁律拒绝（如 `0x06 mode=0` 关广播）、`0xFF`=空贴（无命令）。
- 也可用 BLE 连 web_uploader 看电量 / 当前页（BLE 本就常开）。
- 若状态没变：见 §8 排错。

---

## 8. 排错

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 贴了没反应 | 没写 magic / 校验失败 | 确认整帧以 `A5` 开头且 `sum` 正确（§4） |
| 反复翻页 | 贴着不动重复触发 | 拿开后重贴；固件已用 IRQ 沿 + 清 magic 防重，正常不会 |
| 校时差 8 小时 | 时间戳用了北京时间没减 8h | 时间戳必须 UTC（§5） |
| 文本被当乱码 | App 用 UTF-8 编码高位字节 | 改用 §3-A 文本十六进制串（最稳） |
| iOS 校时不灵 | iOS 写不了动态时间戳 | 用安卓代写，或退回 BLE 校时 |

## 9. 待真机实测钉死（v15.2 已实现，但 EEPROM 布局未上机验证）

- **FM11NC081 用户 EEPROM 基址 `0x0010`** 与扫描窗口（`NFC_CMD_SCAN_LEN=192`）来自数据手册 /
  HiHope 参考例程；若真机读回全 `0xFF` 或帧偏移错位，需抓 I2C 确认实际 NDEF 布局后调整
  `nfc.c` 里的 `NFC_E2_BASE` / `NFC_CMD_SCAN_LEN`。
- **NDEF 文本记录的头部字节**：手机 Text 记录会带 NDEF 头（TNF/类型长度/负载长度/类型 `T`），
  纯文本 `A50100A4` 落进 EEPROM 时前面有几字节头——固件用 `magic 0xA5` 任意偏移滑窗扫描仍能命中；
  若实测发现某些 App 把文本做了 URL 前缀等包装，以「数据/自定义记录」裸字节形态写更稳。
- **EEPROM 擦写寿命**：每次贴卡写 16 字节状态块（+ 有命令时清 1 字节 magic）；日常偶发贴卡可忽略。
- 校验和算法：**保持 8 位 XOR**（与 §1 一致），未改动。

## 附：自验脚本（Python）

```python
def frame(cmd, payload=b''):
    b = bytes([0xA5, cmd, len(payload)]) + payload
    s = 0
    for x in b:
        s ^= x
    return (b + bytes([s])).hex().upper()

print(frame(0x01))                                 # A50100A4
print(frame(0x04, int(1789287895).to_bytes(4, 'big')))  # A504046AA65DD7E3
```
